# Колесо возможностей · ТИАН-Трейд

Одностраничный сайт на GitHub Pages с общей базой данных Supabase.

## Настройка (один раз)

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. В Supabase → **SQL Editor** выполните [supabase/setup.sql](supabase/setup.sql). Будут созданы таблицы, защищённые политики доступа, серверный розыгрыш и исходные 12 призов.
3. В **Authentication → Users → Add user** создайте администратора с его email и выбранным паролем. При необходимости подтвердите email. Используйте ранее выбранный пароль в форме Supabase Auth: он не должен попадать в репозиторий.
4. Выполните в **SQL Editor** (замените email):
   ```sql
   insert into public.fortune_admins (user_id)
   select id from auth.users where lower(email) = lower('YOUR_ADMIN_EMAIL')
   on conflict do nothing;
   ```
5. В [supabase-config.js](supabase-config.js) укажите **Project URL** и **publishable key** (либо legacy anon key), доступные в **Project Settings → API Keys**. Это публичный ключ. **Никогда не размещайте service_role или secret key в коде сайта.**
6. В GitHub → **Settings → Pages** включите **Deploy from a branch → main / (root)**.
7. Откройте https://surniiyka-cloud.github.io/koleso_fortun/ и проверьте вращение и вход администратора.

## Что умеет сайт

- 12 секторов, в том числе антикарточка с предложением крутить повторно.
- Серверная случайная выдача через SQL RPC, не клиентское подбрасывание результата.
- Не более одного выигранного подарка и одной антикарточки на одинаковые имя и фамилию.
- Синхронизация результатов между устройствами.
- Защищённая админка: управление призами и просмотр истории; CSV/JSON экспорт.

## Безопасность и ограничения

- История доступна только авторизованным администраторам (RLS); серверная функция выдаёт только полученный приз.
- Админ входит **по email и паролю**, созданным в Supabase Auth. Предыдущая HTML-проверка пароля заменена.
- Импорт JSON и удаление истории из веб-интерфейса отключены из соображений безопасности.
- Имя и фамилия **не подтверждают личность**: любой человек может ввести чужое имя. Перед реальным мероприятием рекомендуется выдавать уникальные коды или использовать учётные записи сотрудников.
- Открытый анонимный RPC потенциально подвержен автоматизированным массовым запросам. Для публичного развертывания рекомендуется добавить CAPTCHA и серверное ограничение частоты запросов.
- Экран истории показывает последние 2000 розыгрышей.
- Старые локальные данные предыдущей версии не импортируются автоматически.

## Рекомендации по проверке

Проверьте: вход сотрудника; выпадение антикарточки и повторную прокрутку; блок повторного выигрыша; смену имени; вход и выход администратора; отображение истории с другого устройства; запрет анонимного чтения истории.
